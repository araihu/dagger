# Arai Hû Dagger modules

Small, organization-wide CI primitives for Dagger Engine v0.21.8:

| Module | Contract | External side effects |
| --- | --- | --- |
| [`go`](./go) | Pinned Go test, vet, generate, and build | None |
| [`node`](./node) | Pinned npm install and script execution | None |
| [`generated`](./generated) | Native `Changeset` and drift assertion | None |
| [`verified-download`](./verified-download) | HTTPS file verified by SHA-256 | Download only |

Project-specific orchestration remains in the consuming repository. These modules deliberately do not publish, deploy, release, or integrate review bots.

## Immutable consumption

Pin every remote module to the full reviewed commit SHA, never a moving branch:

```sh
dagger -m github.com/araihu/dagger/modules/<module>@<40-character-commit> call ...
```

Tags can improve discoverability, but the consumer configuration should retain the resolved commit pin. Update that pin only through a reviewed dependency change.

## Cache boundary

Public Go and Node primitives intentionally mount no persistent `CacheVolume`.
Until shared Engine isolation is enforced outside module-controlled source, no
caller-provided namespace or trust string may select mutable shared storage.
Dagger's ordinary immutable operation cache remains available within Engine policy.

## Development gate

Each directory is an independent Go SDK module. Run `dagger develop` in each module after changing its public API, commit the regenerated Go SDK bindings, then validate it with Dagger Engine v0.21.8. Pure input and command contracts are testable without the engine:

```sh
set -euo pipefail
for module in go node generated verified-download; do
  (
    cd "modules/$module"
    DAGGER_SESSION_PORT=1 DAGGER_SESSION_TOKEN=offline-test go test ./...
  )
done
```

The placeholder session values let generated client packages initialize for
host-only unit tests; those tests must not query Dagger. Runtime contracts run
separately through the exact CLI and real Engine session.

Committed `dagger.gen.go`, `internal/dagger/dagger.gen.go`, `go.mod`, and
`go.sum` files are generated by Dagger v0.21.8. CI reruns `dagger develop` and
rejects any generated drift before executing module contracts.
